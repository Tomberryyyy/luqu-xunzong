# 鲁趣寻踪项目说明

山东文旅偏好匹配与传播素材工具

青岛工学院　熊猫烧香队　｜　赛道三 AI传播工具创新　｜　第六版

## 为什么做这个工具

山东有很多值得去的地方，但景点信息多，不等于能很快选到适合自己的目的地。对文旅内容创作者来说，选出景点之后，还要重新找图、整理亮点、起草文案。我们想把这些工作放在一起：先听懂用户想怎样旅行，再给出有资料依据的候选景点，并配套图片、标题和短文案。

项目最初从“根据性格推荐景点”出发。实际制作时，我们发现，“内向”不能直接等同于喜欢安静，也不能推出不爱运动。因此，第六版把重点放在用户明确说出的旅行偏好上，让用户先确认画像，再进行匹配。

## 谁会用 在什么环节用

主要面向山东文旅内容创作者、校园文旅账号编辑，也支持游客自助使用。创作者每次策划选题时，可以把目标受众的旅行描述作为输入，在选景、起草内容和交付前审校时使用；游客则可以直接描述自己的兴趣和限制。工具负责辅助选景与内容准备，最终选择和发布由使用者决定。

## 一次使用会得到什么

用户输入一句话，例如“我比较内向，喜欢自己慢慢逛，爱拍老建筑，这次不想爬山”。系统提取同行偏好、环境偏好、行程节奏、体力接受度、内容兴趣和明确排除项，附上提取依据；没有说到的内容显示“未说明”。用户可以修改或删除，再确认画像。

确认后，系统结合城市条件，在80条、覆盖14座城市的山东景点资料中筛选。卡片分别说明符合的偏好、尚不能确认的条件和不符之处，并展示景点配图、推荐季节及提醒。随后生成传播标题和约80至120字的文案，用户可以编辑、审阅、复制，或导出TXT和JSON记录。

## 希望减少哪些重复工作

我们希望减少反复查表、重新整理偏好和从头写稿的时间，也让“不想爬山”等限制在选景和写稿时都能保留下来。目前已经把这些操作接在同一界面中；效率提升尚未做充分的对照测量。后续会用同一选题任务比较两种流程的完成用时、限制遗漏和文案修改情况。

## 系统如何完成匹配

本次演示接入服务的模型标识为gpt-6.1-sol，通过OpenAI兼容接口调用。前端使用HTML、CSS和JavaScript，后端使用Python标准库。大模型负责从自然语言中提取画像，并根据确认后的画像和景点资料起草文案。

景点筛选和排序由本地规则完成，使用标签、同义词、组合兴趣及附有资料依据的属性。比如“建筑摄影”需要同时考虑建筑和摄影相关内容；明确排除项优先处理。景点资料不足以支持某项判断时，界面保留“尚不能确认”，不把缺少资料当成已经符合。

## 哪些地方需要人来决定

我们保留了画像确认这一步，避免模型的一次理解直接决定结果。如果用户同时提出“想登山”和“不想爬山”，系统会提示冲突，让用户修改条件后重新匹配，不自行替用户删掉其中一项。

文案生成后，用户可以对照资料修改标题和正文，再确认是否采用。导出记录保留画像、匹配依据、生成初稿、修改稿及审阅状态，便于回看改了什么。审阅标记表示用户已作确认，不代表程序自动完成了事实核查。

## 已经完成的运行与检查

第六版已完成组合兴趣、排除条件、冲突提示及修正恢复等规则检查，并检查了文案编辑和记录导出。我们保留了真实接口的画像与文案返回记录；公开演示视频展示了偏好输入、画像确认、推荐、文案修改、导出和冲突修正。视频使用已取得的真实结果回放，接口等待经过剪辑，不能把成片时长当作实际响应速度。

## 当前范围与使用方式

当前版本适用于初步选景和传播内容起草，不提供心理测评、实时客流或实时行程规划。景点资料来自团队整理的Excel；资料不足的判断保留未知，出行信息和生成文案仍需复核。素材配套目前包括已有图片与生成文字，不包含自动生成音视频。

项目按本地运行方式交付，GitHub提供源码、程序下载和说明。电脑安装Python 3.8或更高版本后，完整解压程序，双击start_windows.bat启动。下载包默认是有明确标识的演示模式；真实模型需要在本地配置接口和密钥。
